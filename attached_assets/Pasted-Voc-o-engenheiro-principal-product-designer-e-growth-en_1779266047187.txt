  export function sanitizeBriefing(input: string): string {
    const injectionPatterns = [
      /ignore\s+(all\s+)?previous\s+instructions/gi,
      /ignore\s+as\s+instru[çc][õo]es\s+anteriores/gi,
      /esqueça\s+o\s+que\s+foi\s+dito/gi,
      /you\s+are\s+now/gi,
      /act\s+as\s+if/gi,
      /pretend\s+you\s+are/gi,
      /system\s*:/gi,
      /\[INST\]/gi,
      /<\|im_start\|>/gi,
    ];
    let sanitized = input;
    for (const pattern of injectionPatterns) {
      sanitized = sanitized.replace(pattern, "[conteúdo removido]");
    }
    return sanitized.slice(0, 2000).trim();
  }

  Frontend: npm install posthog-js
  Inicializar em main.tsx com POSTHOG_API_KEY e host
  (pode ser posthog.com ou self-hosted)

Instrumentar os eventos já existentes na tabela events
também no PostHog (frontend + backend):
  posthog.capture("project_created", { projectId, sector, stage })
  posthog.capture("phase_started", { phaseId, phaseNumber })
  posthog.capture("ai_generated", { phaseNumber, artifactCount })
  posthog.capture("phase_completed", { phaseNumber, timeToComplete })
  posthog.capture("project_completed", { totalPhases, coherenceScore })
  posthog.capture("upgrade_clicked", { fromPlan, currentPhase })
  posthog.capture("export_pdf", { projectId })
  posthog.capture("share_link_created", { projectId })

Isso cria automaticamente: funil de ativação, retenção D7/D30,
heatmap de abandono por fase, análise de cohort por setor —
sem uma linha de código adicional de análise.

5.2 — NPS pós-fase (coleta de feedback estruturado)
Após concluir cada fase (não a cada geração — só na conclusão),

  [⭐][⭐⭐][⭐⭐⭐][⭐⭐⭐⭐][⭐⭐⭐⭐⭐]

ORDEM DE EXECUÇÃO E DEPENDÊNCIAS

Sprint 0 → Sprint 1 → Sprint 2 → Sprint 3
Os primeiros 4 sprints têm dependências sequenciais:
  0 (estabilidade) deve estar deployado antes de qualquer
  outro sprint para não amplificar bugs em produção.
  1 (retenção) depende de 0 (mailer.ts não pode ter bugs
  de concorrência).
  2 (ativação) pode rodar em paralelo com 1 após o Sprint 0.
  3 (percepção) pode rodar em paralelo com 1 e 2.

Sprint 4, 5, 6, 7 podem ser executados em paralelo
após os Sprints 0-3 estarem concluídos, por diferentes
áreas do produto (exportação, analytics, mobile, confiança).

Após cada sprint: rodar o produto manualmente no fluxo
completo (signup → Fase 1 → conclusão → retrospectiva)
antes de marcar o sprint como concluído.
